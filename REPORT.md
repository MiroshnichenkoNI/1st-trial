# Обработка видео: DOVER и Qwen

**Решения.** Для каждого видео DOVER вычисляет техническую и эстетическую оценки, Qwen3-VL-2B-Instruct формирует описание. Оба режима используют одинаковые модели и настройки.

- **Baseline:** обработка группами по четыре видео. Сначала DOVER оценивает группу, затем Qwen генерирует описания. Следующая группа поступает после завершения всей предыдущей. Подготовка кадров выполняется заранее на CPU.
- **Optimized:** одновременно обрабатываются до четырёх запросов Qwen. Завершившийся запрос заменяется следующим, без ожидания всей группы. CPU заранее готовит два видео; DOVER может оценивать новое видео во время работы Qwen.

В обоих режимах батчингом Qwen управляет vLLM через AsyncLLM. Обе модели размещены на одной GPU.

**Настройки моделей.**

- **DOVER:** официальные веса и подготовка входов, FP32,
- **Qwen:** FP16, около двух кадров в секунду, бюджет 8 388 608 пикселей на видео. Запрос: «Сгенерируй детальное описание всего, что происходит на видео». Звук не используется.
- **Генерация:** максимум 768 новых токенов; `temperature=0.7`, `top-p=0.8`, `top-k=20`, `seed=42`. Штраф 1.5 применяется к токенам из последних 256 позиций промпта и ответа.
- **vLLM:** контекст до 8192 токенов, до четырёх запросов, бюджет 60% памяти GPU (чтобы dover влез). Кеширование общего префикса отключено.

**Результаты.** Замер выполнен на Tesla V100 32 GB: один запуск baseline и один optimized. После прогрева каждый обрабатывал 50 видео — пять повторов набора. Сравнивалось время между 12-м и 32-м завершениями: каждое видео попадало в окно дважды.

| Режим | Время окна из 20 видео |
|---|---:|
| Baseline | 70,833 с |
| Optimized | 66,370 с |

**Что еще пробовал:**

1. Пробовал изначально делать на Mac. Гибрид Core ML и MLX ускорял поток - на МАКЕ, но vLLM не ставилась
2. Пробовал запускаться на Transformers + Pytorch на двух 1080 TI, где пайп:

   - Копия QWEN на каждой, DOVER и асинхронная подача в очередь видео показала лучший результат

3. Перераспределение GPU-памяти, фоновый DOVER и NVIDIA MPS не показали убедительного преимущества - на v100 для того, чтобы DOVER и QWEN не боролись за ресурсы

**Дальнейшие ускорения при большом бюджете ресурсов, в порядке приоритета.**

1. **Современные GPU и несколько копий моделей.** Распределять независимые видео между GPU; отдельно проверить выделение разных GPU для DOVER и Qwen.
2. **Настройка загрузки Qwen.** Подбирать число активных запросов и группировать видео близкого размера, учитывая память и задержку ответа.
3. **Точность вычислений.** На подходящем оборудовании проверить FP8/INT8 для Qwen и смешанную точность DOVER. BF16 может улучшить численную устойчивость относительно FP16, но не уменьшает память.
4. **Подготовка кадров.** При простоях GPU проверить аппаратное декодирование, больше подготовщиков и предварительное чтение видео.
5. **Повторяющиеся вычисления.** Кешировать токенизацию постоянного текста промпта. Для короткой инструкции эффект ожидается небольшим; общий текст после видео сам по себе не позволяет переиспользовать вычисления префикса модели.
